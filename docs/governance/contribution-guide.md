# Guide de contribution

## Règles de base

- lire la documentation avant de modifier le projet,
- distinguer l’état actuel et l’état cible,
- ne pas inventer d’architecture non observée,
- documenter les changements majeurs,
- garder la simplicité de conception,
- éviter d’ajouter du code ou de la complexité inutile.

## Avant de modifier le code

- comprendre la page ou le module touché,
- repérer les dépendances et les impacts,
- déterminer si la modification relève du site public ou de la Gestion interne.

## Validation

- vérifier le comportement sur les pages concernées,
- valider la navigation,
- vérifier la sécurité et les dépendances,
- respecter les règles de l’ADR et RFC pour les changements importants.
