# Roadmap du projet

## Phase 0 — Audit et documentation

- documenter le projet actuel,
- identifier les dépendances,
- définir le périmètre technologique,
- distinguer site public et Gestion interne.

## Phase 1 — Stabilisation du site public

- sécuriser les pages publiques,
- réduire les doublons de styles et sections,
- harmoniser navigation et contenus,
- vérifier les parcours clés.

## Phase 2 — Architecture backend

- définir la stack backend si nécessaire,
- structurer les services métier,
- documenter les interfaces d’intégration.

## Phase 3 — Base de données

- formaliser le schéma métier,
- planifier les migrations,
- définir les tables propres à la Gestion interne.

## Phase 4 — Authentification

- définir le système d’authentification,
- créer les profils et permissions,
- sécuriser les flux d’accès.

## Phase 5 — Gestion interne

- développer les modules d’administration,
- créer les services de direction et d’exploitation,
- sécuriser l’accès et les données.

## Phase 6 — Connexion site public / gestion interne

- connecter les contenus de publication,
- synchroniser les données métier,
- mettre en place les permissions de publication.

## Phase 7 — Tests et sécurité

- validation fonctionnelle,
- tests d’intégration,
- revue de sécurité,
- correctifs de vulnérabilité.

## Phase 8 — Déploiement production

- configuration de l’environnement,
- migration réelle,
- mise en place de sauvegardes et de monitoring.

## Phase 9 — Monitoring et maintenance

- journalisation,
- observabilité,
- maintenance continue,
- amélioration de la qualité et de la sécurité.

## Remarque

Cette roadmap est une proposition réaliste à partir de l’état actuel observé. Elle doit être revérifiée lorsque l’environnement produit du Centre sera connu.
